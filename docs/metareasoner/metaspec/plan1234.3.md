# SeNARS MetaReasoner — Ultimate Architecture Specification

---

## §0. Foundational Thesis

**A reasoner is a point in a structured algebra of bounded, governed cognition.**

The MetaReasoner is not a system that is then made configurable. It is a *configuration space* — the **Cognitive Control Algebra** — from which concrete reasoners are evaluated. Every architecture that has been called by a name (SeNARS, AEGIS, Ω-Calculus, Θ, ACS) is one evaluation point. Every architecture not yet designed is an unoccupied coordinate. The algebra is the object; reasoners are its projections.

This thesis inverts the conventional relation between architecture and instance:

| Conventional | MetaReasoner |
|---|---|
| An architecture is designed, then parameterized | An algebra is defined; architectures are its elements |
| Variants fork a codebase | Variants are coordinate selections in one space |
| Control flow is code | Control flow is data — a value in the algebra |
| Resources are quotas | Resources are an economy with prices |
| Mutation is direct writes | Mutation is a governed transaction through one port |
| The scheduler is opaque | Every control decision is a typed, replayable event |

The current SeNARS dual-loop pipeline becomes **SeNARS₀**, a constant configuration. It is not the architecture. It is one evaluation.

### Design Axioms

1. **Universality.** The algebra must be rich enough to express every bounded, governed reasoner — symbolic, neural, hybrid, cellular, thermodynamic, categorical, cybernetic.
2. **Minimality.** The primitive set must be irreducible: no sort can be expressed as a combination of the others.
3. **Compositionality.** Configurations compose. The semantics of a composition is the composition of the semantics: ⟦c₁ ⊗ c₂⟧ = ⟦c₁⟧ ∘ ⟦c₂⟧.
4. **Constitutional closure.** Every configuration in the algebra satisfies the Constitution Φ. Infeasible configurations are rejected at load time, before any cognition runs.
5. **Conservative extension.** Each enrichment tier adds coordinates. No tier invalidates a prior tier's invariants.

## §1. The Cognitive Transaction

All cognition — perception, inference, proposal, judgment, action, learning, forgetting, consolidation, simulation, self-modification — is a single typed unit: the **CognitiveTransaction** (CT).

```typescript
interface CognitiveTransaction {
  id:              TransactionId;
  correlationId:   CorrelationId;       // threaded stimulus → outcome
  kind:            TransactionKind;
  axis:            CognitiveAxis;       // 'epistemic' | 'teleological' | 'governance' | 'learning'
  inputs:          CognitiveObject[];
  outputs:         Candidate[];
  effects:         EffectDeclaration[];
  budget:          BudgetReservation;
  proposer:        ProposerProfile;     // LM | reflex | NAL | peer | self-mod | exact
  trust:           TrustProfile;
  risk:            RiskProfile;
  reversibility:   ReversibilityClass;
  proofObligations: ProofObligation[];
  fallback:        FailurePolicy;
}
```

**Kind vocabulary** (closed enum):

`perception · inference · proposal · judgment · commit · action · learning · forgetting · consolidation · simulation · self-modification · meta-control`

**Axis semantics** (the epistemic firewall, H1):

| Axis | Governs | Truth carrier | Mutated by |
|---|---|---|---|
| `epistemic` | What is believed | `(frequency, confidence)` | Evidence only |
| `teleological` | What is desired | `(desire, confidence)` | Progress, not reward |
| `governance` | What is authorized | Autonomy state | Risk classification |
| `learning` | What is adapted | Policy weights | Trajectories, preferences |

No transaction of axis `teleological` may produce a write to an `epistemic` truth value. No reward signal may mutate `frequency` or `confidence`. This is enforced at the type level (capabilities) and at runtime (ledger normalization).

### §2.1 Topology 𝒯 — Control Structure

Control flow is data. The topology is a directed hypergraph of stages, loops, and nesting depths, expressible equivalently as a KAT control word or a conditional DAG.

```typescript
interface Topology {
  stages:     Map<StageId, StageNode>;
  edges:      StageEdge[];
  entry:      StageId;
  exit:       StageId;
  nesting:    NestingDepth;          // 0 = flat, 1 = loop-in-loop, 2+, …
  tower:      HeterochronousLevel[]; // multi-rate loops, optional
}

interface StageNode {
  id:           StageId;
  kind:         StageKind;
  run:          (ctx: CycleContext) => Promise<CognitiveTransaction[]>;
  budgetScope:  BudgetScopeId;
  failure:      FailurePolicy;
}

interface StageEdge {
  from:      StageId;
  to:        StageId;
  guard:     (ctx: CycleContext) => boolean;
  budget?:   BudgetScopeId;
  parallel?: boolean;
}
```

**KAT control word algebra** (equivalent representation):

| Operator | Symbol | Semantics |
|---|---|---|
| Sequence | `p · q` | Execute p then q |
| Choice | `p + q` | Execute p or q |
| Iteration | `p*` | Repeat p |
| Guard | `b? · p` | Execute p iff b holds |
| Skip | `1` | Identity |
| Parallel | `p ∥ q` | Concurrent fan-out / join |

**Topology operations**: `compose`, `parallel`, `nest`, `restrict`, `lift`.

**SeNARS₀ topology**: three nested loops (macro 8-phase → micro 6-stage → inference), expressed as a conditional DAG where all guards are initially `true`.

### §2.2 Gate Lattice 𝒢 — Oriented Admission

Gates mediate every boundary crossing. Each gate has an **orientation** that determines its default behavior under uncertainty:

- **Interior** (fail-closed): deny unless evidence is sufficient. Used at ingress.
- **Closure** (fail-open): admit unless evidence is contrary. Used at egress.

```typescript
interface Gate {
  id:          GateId;
  orientation: 'interior' | 'closure';
  check:       (ct: CognitiveTransaction) => Promise<GateVerdict>;
}

type GateVerdict =
  | { verdict: 'admit';  trust: TrustProfile }
  | { verdict: 'reject'; reason: RejectionReason }
  | { verdict: 'defer';  condition: ReevaluationCondition }
  | { verdict: 'provisional'; decay: DecaySchedule };
```

**Gate operations**: `meet` (serial conjunction), `join` (parallel disjunction), `fallback` (ordered chain), `vote` (k-of-n quorum).

**Standard gates**: PerceptionGate (ingress), ActionGate (egress authorization), RewardGate (epistemic firewall), BudgetGate (resource admission).

**Trust is measured at gates, not stored globally.** A `TrustProfile` is computed per-transaction from source quality, source reputation, calibrated manifold scores, and corroboration. Gates consume trust profiles; they do not produce global trust states.

### §2.3 Economy ℬ — Resource Budgets, Reservations, Pricing

Resources are not static quotas. They are a **reservation economy** with marginal-utility pricing.

```typescript
interface Economy {
  dimensions:  CostDimension[];     // cycles, derivations, premises, memoryOps,
                                    // llmCalls, tokens, latency, attention, risk, humanAttention
  scopes:      BudgetScope[];       // scoped ceilings with parent/child lattice
  pricing:     PricingModel;
  allocation:  AllocationPolicy;    // 'priority-queue' | 'utility' | 'boltzmann' | 'market'
}
```

**Reservation protocol** (prevents silent starvation):

1. `reserve(bid) → BudgetReservation` — deducts from available before execution.
2. `settle(reservation, actualCost)` — returns unused portion after execution.
3. Denied reservation → typed `BudgetExhausted` event (never silent drop).

**Pricing model** (utility-based scheduling):

```
score(op) = (ΔK + ΔG + ΔH) / (λc·C + λr·R + λh·H)
```

Where ΔK = expected epistemic gain, ΔG = expected teleological gain, ΔH = expected homeostatic gain, C = compute cost, R = risk cost, H = human attention cost.

**Thermodynamic mode** (optional enrichment): Replace deterministic cutoffs with Boltzmann allocation: `P(pursue) ∝ exp(−ΔE / T)`, where T (cognitive temperature) interpolates exploration ↔ exploitation.

**Graceful degradation under pressure**:

| Pressure | Behavior |
|---|---|
| Low | Explore, enrich, elaborate |
| Medium | Prioritize goals and proofs |
| High | Conserve, degrade to symbolic, request human attention |

### §2.5 Substrate 𝒮 — Terms, Truth, Revision

The substrate is the reasoning material: the term algebra, the truth-value algebra, and the revision operation.


**Truth algebra variants**: Boolean, probabilistic, NAL `(frequency, confidence)`, Dempster-Shafer, fuzzy, paraconsistent (graded, multi-sorted).

### §2.6 Memory Model 𝓜 — Bounded, Port-Based Storage

Memory is accessed exclusively through typed ports. No component holds a direct reference to the memory implementation.

```typescript
interface MemoryModel {
  ports: MemoryPorts;       // 9 named contracts
  decay: DecayPolicy;       // truth decay ⊥ attention decay
  consolidation: ConsolidationPolicy;
  capacity: CapacityBounds;
}
```

**Nine memory ports**: `ConceptReader`, `ConceptWriter`, `TaskAdmission`, `BeliefTable`, `GoalEnumeration`, `LinkPort`, `StatisticsView`, `SymbolIndex`, `MemoryClock`, `AttentionOwner`.

**Write authority**: Only the CommitLedger holds `ConceptWriter` and `TaskAdmission`. No other component writes to memory directly.

**Decay separation**: Truth values (`frequency`, `confidence`) decay only on temporal invalidation or contradiction. Attention (`priority`) decays by LRU/access time. These are independent axes.

## §3. The Constitution Φ

Every configuration must satisfy Φ at load time. Infeasible configurations are rejected before instantiation. These are the ten hard constraints, stated formally.

| ID | Law | Formal statement |
|---|---|---|
| **H1** | Epistemic firewall | `∀ tx : CT, tx.axis = teleological ⇒ tx ∉ writers(Belief.truth)` |
| **H2** | Untrusted ⇒ judged | `∀ p : Proposal, proposer(p) = untrusted ⇒ judged(p) before commit(p)` |
| **H3** | Mutation ⇒ event | `∀ write, ∃ ledger entry; admit-before-write` |
| **H4** | No self-approval | `∀ self-mod, authority ∈ {external, governed-arbitration}; never self` |
| **H5** | Boundedness | `∀ reasoning path, bounded in time ∧ memory ∧ derivations ∧ LM calls` |
| **H6** | No opaque scheduling | `∀ scheduler decision, decision ∈ EventLog; control-plane provenance` |
| **H7** | Verifier independence | `imports(verifier) ∩ imports(engine) = ∅; drift pinned by test` |
| **H8** | Equality isolation | `exact-substrate ∪ uncertain-similarity = ∅; arbiter pattern enforced` |
| **H9** | No silent faults | `∀ fault affecting cognition/budget/admission, fault ∈ typed events` |
| **H10** | Irreversibility ⇒ authorization | `irreversible(action) ⇒ risk-classified(action) ∧ authorized(action)` |

**Type-level encoding** (where possible):

| Constraint | Encoding |
|---|---|
| H1 | `BeliefWriter` requires `EvidenceOnly` capability; `Reward` lacks it |
| H2 | `UntrustedProposal` requires `JudgeResult` to construct `CommitCandidate` |
| H3 | `CommitLedger.commit` returns `EventId`; no other write method exists |
| H4 | `SelfModProposal` requires `ExternalApproval` token to commit |
| H5 | `CognitiveTransaction` requires `BudgetReservation`; unbounded ⇒ reject |
| H6 | `SchedulerDecision` is a `CT { kind: 'meta-control' }` |
| H7 | Verifier package has dependency-direction rule forbidding engine imports |
| H8 | `ExactSubstrate` port has no `unionOnSimilarity` method |
| H9 | `FailurePolicy` is required on every CT; `Result` type forces handling |
| H10 | `IrreversibleAction` requires `RiskClassification ∧ Authorization` to construct |

**Config-time validation**: `validateConfig(c) → { feasible: boolean; violations: ΦViolation[] }`. Called by the evaluator before any instantiation.

## §4. The Evaluator ⟦·⟧

The evaluator is the single function that transforms a `ReasonerConfig` into a runnable `Reasoner`.

```typescript
function evaluate(c: ReasonerConfig): Reasoner {
  // 1. Validate Φ(c) — reject if infeasible
  // 2. Build substrate from c.substrate
  // 3. Construct topology from c.topology (compile KAT → DAG if needed)
  // 4. Wire gate lattice from c.gates
  // 5. Install economy from c.economy (budget office, pricing)
  // 6. Resolve strategy slots from c.strategies
  // 7. Compose memory from c.memory (ports, decay, consolidation)
  // 8. Install policy from c.policy (failure, degradation, reflexivity)
  // 9. Wire provenance from c.provenance (event log, correlation, verifier)
  // 10. Construct the single CommitLedger (single write authority)
  // 11. Return runnable Reasoner with graph runner
}
```

**Evaluator guarantees**:

1. **Single commit authority.** The evaluated reasoner has exactly one `CommitLedger`. All mutation paths route through it. No bypass exists.
2. **Event-sourced state.** State is a fold of the append-only event log. `replay(events) ≅ state`. Snapshots are checkpoints, not sources of truth.
3. **Constitutional closure.** If Φ(c) fails, `evaluate` throws before constructing anything.
4. **Deterministic replay.** Given the same event sequence, the fold produces the same state. Hash verification confirms this.

**Compositionality**: `⟦c₁ ⊗ c₂⟧ = ⟦c₁⟧ ∘ ⟦c₂⟧`. Configurations compose; the evaluator distributes over composition.

## §6. The Control Graph Runner

The hard-coded stage loop is replaced by a graph runner that executes the topology as data.

```typescript
async function runGraph(
  graph: Topology,
  ctx: CycleContext,
  signal: AbortSignal
): Promise<CycleResult> {
  let node = graph.entry;
  while (node !== graph.exit && !signal.aborted) {
    const stage = graph.stages.get(node);
    const reservation = ctx.economy.reserve(stage.budgetScope, estimate(stage));
    try {
      const txns = await stage.run(ctx);
      ctx.economy.settle(reservation, actualCost(txns));
      for (const tx of txns) await ctx.ledger.commit(tx, ctx.commitContext);
    } catch (e) {
      ctx.economy.settle(reservation, { wasted: true });
      ctx.policy.handle(e, stage, ctx);   // H9: typed fault event
    }
    // Evaluate outgoing edges
    const next = graph.edges
      .filter(e => e.from === node)
      .find(e => e.guard(ctx));
    node = next?.to ?? graph.exit;
  }
}
```

**Guards enable conditional execution**: stage skipping, fast-paths, heterochronous loops, parallel fan-out. The graph is A/B-testable. Control decisions are logged as `CT { kind: 'meta-control' }` (H6).

## §8. The Reflexivity Tower

Self-modification is governed by a strict filtration. No level is self-approved. Truth (𝒱) sits outside the tower entirely.

```
F₄  Constitution / governance     ← Human + external audit
F₃  Code / config patches         ← Shadow CI + external immutable arbiter
F₂  Rules (schema induction)      ← Proof + shadow validation
F₁  Strategy selection            ← Proposal or auto
F₀  Knobs / parameters            ← Auto or low-risk
```

**Meta-controller as governed proposer**: The scheduler/controller is itself a CT of kind `meta-control`. It observes through the same perception ports, reasons through the same inference substrate, proposes control-word edits through the same proposal pipeline, is judged by the same governance manifold, and is budgeted by a dedicated `control-work` scope.

**Controller portfolio** (swappable, blendable):

| Controller | Behavior |
|---|---|
| Deliberative | Deep inference, high proof burden |
| Reactive | Fast reflexes, low latency |
| Curious | Exploration, question generation |
| Conservative | High rejection threshold, low risk |
| Creative | High proposal diversity, sandboxed |
| Social | Clarification-seeking, human-in-loop |
| Repair | Contradiction resolution, test fixing |
| Consolidating | Decay, schema induction, integration |

**Hot-swap protocol**: Controller changes occur only at cycle boundaries. State is preserved. The swap is a logged event: `control.hotSwap { from, to, preservedState, cycleBoundary }`.

**Self-modification pipeline**:

```
Observation → Lesson → Hypothesis → Proposal
  → Shadow Execution (worktree / sandbox / simulation)
  → Validation (CI, proof, benchmark, drift test)
  → Risk Classification
  → Governance Gate (autonomy level)
  → Bounded Deployment (cycle-boundary hot-swap)
  → Trace Evaluation → Retention | Rollback
```

## §10. Composition Laws

Configurations compose via typed operations. These are the algebra's structural laws.

| Operation | Symbol | Semantics |
|---|---|---|
| Sequential | `c₁ ⊗ c₂` | Run c₁ then c₂ |
| Parallel | `c₁ ⊕ c₂` | Run concurrently, join |
| Restriction | `c \| P` | Project onto capability subset P |
| Refinement | `c₁ ⊑ c₂` | c₁ is a behavioral subset of c₂ |
| Lifting | `lift(c, F)` | Apply functor F to every component |
| Nesting | `nest(c, depth)` | Wrap c in n levels of loop |
| Abstraction | `α(c)` | Behavioral equivalence class |

**Compositionality axiom**: `⟦c₁ ⊗ c₂⟧ = ⟦c₁⟧ ∘ ⟦c₂⟧`. The semantics of a composition is the composition of the semantics. This enables independent optimization of parts.

**Conservative extension**: Each tier adds coordinates. No invariant moves. `Ω₀ ⊑ Ω₁ ⊑ Ω₂ ⊑ Ω₃ ⊑ Ω₄`.

## §13. Extension Model

The algebra is open. New control models, substrates, and governance policies plug in through typed ports.

### Extension Points

| Extension | Port | Current | Future possibilities |
|---|---|---|---|
| Substrate | `SubstratePort` | NAL, MeTTa | Quantum, neuromorphic, DNA |
| Scheduler | `MetaController` | Fixed, portfolio | Learned, market, swarm |
| Judge | `JudgePort` | System One manifold | Constitutional AI, formal verification |
| Memory | `MemoryPorts` | Bounded bags | Holographic, associative, persistent |
| Governance | `GovernancePort` | Lattice + risk manifold | DAO, constitutional, prediction market |
| Provenance | `ProvenanceBackend` | SQLite / JSONL | Merkle-DAG, IPFS |

### Adding a New Flavor

A new control model requires **zero framework changes**:

1. Define a `ReasonerConfig` constant with the desired coordinates.
2. Validate against Φ at load time.
3. Register in the `FlavorRegistry`.
4. `evaluate(newFlavor)` produces a runnable reasoner.

### Constitutional Extensibility

New hard constraints can be added to Φ without breaking existing configurations:

```typescript
// Future: H11 — no cross-agent belief fusion without independence accounting
if (config.ecology?.enabled && !config.provenance?.independenceAccounting)
  violations.push({ constraint: 'H11', ... });
```

## §14. Invariants & Verification

### Runtime Invariants

| Invariant | Mechanism |
|---|---|
| Single write authority | Only `CommitLedger.commit` writes to memory |
| Epistemic firewall | Axis check in ledger pipeline; type-level capability separation |
| Bounded cognition | `BudgetReservation` required on every CT; AIKR bounds |
| Event-sourced mutation | Every write produces a ledger entry; no unlogged mutation |
| No self-approval | `SelfModProposal` requires external token; F₀–F₄ filtration |
| No silent faults | `FailurePolicy` required; all faults are typed events |
| Verifier independence | Dependency-direction rule; drift pinned by test |
| Equality isolation | Exact substrate has no `unionOnSimilarity`; arbiter pattern |

### Verification Strategy

| Level | What | How |
|---|---|---|
| Unit | Each algebraic operation | Equational tests: `compose`, `restrict`, `lift` |
| Integration | `evaluate(c)` per flavor | Produces runnable reasoner |
| Property | Compositionality | `⟦c₁ ⊗ c₂⟧ = ⟦c₁⟧ ∘ ⟦c₂⟧` |
| Invariant | Φ validation | All flavors pass at load time |
| Regression | SeNARS₀ parity | `evaluate(SeNARS₀)` ≡ current behavior (E2E gate) |
| Replay | Determinism | `replay(events) ≅ state` for all flavors |
| Drift | Verifier independence | Truth-table divergence measured, not assumed zero |
