# Ω — The Cognitive Control Algebra
## Ultimate Architecture Specification · SeNARS MetaReasoner

**Thesis.** A reasoner is not an architecture. It is a *point in an algebra.* The four development plans (`abstract.plan.1–4`) were four projections of the same object viewed from different angles — ports, sorts, primitives, phases. This specification is the object itself: a universal, modular control-model framework in which the current SeNARS is one evaluated point (`SeNARS₀`), every `synth/` flavor is another, and every future reasoner is an unexplored coordinate of the same space.

**The shift.**

| From (current SeNARS) | To (Ω) |
|---|---|
| Hard-coded 6-stage loop + 8-phase macro-cycle | Control flow is **data** (control words / conditional DAGs) |
| Four ad-hoc gates + policy engine | One **admission functional**, oriented per boundary |
| Static integer quotas | A **resource economy** (reservations + prices) |
| Many mutation paths (`authorize`, `processPending`, tool results, learning, self-mod) | One **commit ledger** — single write authority |
| Event log bolted on | State **is** the event fold — provenance by construction |
| Learning mutates state | Learning **proposes**; governance **decides** |
| LM as implicit authority | LM as untrusted proposer; everything judged |

## §1 — The Reduction

Five plans worth of machinery collapse to **five ones**. Every redundancy across the plans and the current implementation is eliminated here, once, at the root.

| # | Redundancy eliminated | Resolution |
|---|---|---|
| 1 | `Task`, `Derivation`, `Proposal`, `ToolGoal`, `LearningUpdate`, self-mod patches as separate types | **One unit of work** — `CognitiveTransaction` (§4) |
| 2 | `memory.addTask`, `RuleTableStore.admit`, `ToolManager.execute`, `authorize`, `processPending` as separate write paths | **One write authority** — `CommitLedger` (§4) |
| 3 | PerceptionGate, ActionGate, RewardGate, BudgetGate, PolicyEngine, autonomy ladder as separate mechanisms | **One admission functional** `A_θ`, instantiated with different orientations (§7) |
| 4 | `KernelBudgetGate` + `ControlBudgets` + `BudgetSlice` + scope table + three spend arithmetics | **One economy** — a single `CostVector` over one semiring (§6) |
| 5 | `CycleTrace` + `EventLog` + derivation traces + session logs as parallel systems | **One provenance fold** — state ≡ fold(log) (§8) |

Further structural collapses (plan-level redundancies):

- **7 sorts vs 8 primitives vs 5 ports** → **six coordinates** (§3). Valuation and memory are properties of the substrate, not separate sorts. Trust, risk, and failure policy are parameters of admission, not separate sorts. Stage graphs are control, not a separate sort.
- **SeNARS-SG / JC / BB / MC as separate models** → they are **axis values**, not flavors: `κ.scheduler = 'claim-queue'` (BB), `α.trust = 'continuous-field'` (JC), `κ = learned` (MC), conditional DAG (SG). No new machinery; just coordinates.
- **The 4 gates** → four *named call sites* of one functional. The RewardGate becomes the epistemic-firewall clause of `A_θ`; the BudgetGate becomes the `spend` effect.
- **`Memory` god-object** → substrate-owned storage behind nine port contracts, writable **only** through the ledger.

**Conservation law of the reduction:** nothing the current system can do is removed — every eliminated mechanism reappears as a *configuration* of what replaces it, and `⟦SeNARS₀⟧` remains behaviorally identical to today's runtime (§14).

## §2 — Kernel Ω₀: The Five Effects

The irreducible kernel is not a set of subsystems but a **signature of five cognitive effects**. Every stage, every loop, every flavor is a program in this signature; the kernel is its handler.

```text
admit  : Stimulus × Orientation  →  Tx?          — what enters
infer  : State × Grant           →  Tx*          — what derives
spend  : Scope × Cost            →  Grant | Fault — what is paid
record : Event                   →  Log          — what is remembered
commit : Tx × Context            →  Decision     — what becomes true
```

**Kernel laws** (all enforced by construction, not convention):

| Law | Statement |
|---|---|
| K1 | Every ingress passes `admit`; nothing enters unjudged at a fail-closed boundary |
| K2 | No `infer` runs without a `spend` grant — inference is bounded by construction (AIKR) |
| K3 | `commit` is the **only** writer of durable state |
| K4 | Every `commit` is `record`ed **before** it is applied — admit-before-write |
| K5 | `state ≡ fold(log)` — replay reconstructs; the snapshot is a cache, never a source |

Five effects, one transaction type, one fold: this is Ω₀. Everything in the rest of this specification is *denotation* — interpretation of these effects under richer configurations. The kernel is the smallest governed reasoner that can exist; nothing smaller satisfies the Constitution (§13).

## §4 — The Transaction & The Ledger

### 4.1 One unit of work

```ts
interface CognitiveTransaction {
  id: TransactionId;  correlationId: CorrelationId;
  kind: 'perception' | 'inference' | 'proposal' | 'judgment' | 'commit'
      | 'action' | 'learning' | 'forgetting' | 'consolidation'
      | 'simulation' | 'self-modification' | 'control';
  axis: 'epistemic' | 'teleological' | 'governance' | 'learning';
  inputs: CognitiveObject[];   outputs: Candidate[];
  effects: EffectDeclaration[];
  budget: BudgetReservation;
  proposer: ProposerProfile;                    // LM | reflex | NAL | peer | self-mod
  trust: TrustProfile;       risk: RiskProfile;
  reversibility: ReversibilityClass;
  proofObligations: ProofObligation[];
  fallback: FailurePolicy;
}
```

Every cognitive act — perceiving, deriving, proposing, acting, learning, forgetting, scheduling itself — is one of these. There is no other way to do cognition inside Ω.

### 4.2 One write authority

```text
commit : Tx × Context → Decision

Normalize → TypeCheck → AxisFirewall(Φ1) → EvidenceIndependence
  → Prove / Judge / Simulate → Rank(β) → BudgetSettle
  → RiskClassify(α) → Decide
Decision ∈ { commit | shadow-commit | provisional | defer | reject | clarify }
```

- `provisional` commits carry decay and can be revoked by later evidence.
- `shadow-commit` runs in a sandboxed twin; promotion is itself a transaction.
- `clarify` converts an admission failure into a question task (abstention is cognitive, not silent).
- The ledger emits one typed event per decision; the event log is the cryptographic source of truth; JSON state is checkpoint-only.

## §5 — Control Words (κ)

Control flow is **data**: a KAT (Kleene Algebra with Tests) expression with three interchangeable representations.

```text
κ ::= stage(s) | κ·κ | κ+κ | κ* | p?·κ | κ∥κ | 1
      seq       choice  iter  guard   parallel skip
```

- **KAT form** — for formal analysis and equivalence checking.
- **Conditional DAG form** — nodes = stages (each with budget scope, gates, failure policy), edges = guarded transitions with traversal cost. This is the runtime form.
- **Stage-graph form** — for visualization and editing; bidirectional with KAT.

`SeNARS₀` is the word `perceive · attend · reason · authorize · propose · learn` with two guarded escape edges (`starved → triage`, `aborted → exit`) — exactly today's loop, now expressed instead of hard-coded. Skipping, reordering, fan-out, heterochronous re-entry are all just *other words*.

**Graph invariants** (checked at load time, type-level where possible):

1. No path `infer →* commit` without an intervening `verify`.
2. No `teleological` stage may reach a belief-writing commit (Φ1, structurally).
3. Every node declares a budget scope; every `commit`/`act` node declares gates.
4. No untrusted commit without a judge score (Φ2).
5. The graph is well-founded under budget — infinite iteration requires a decreasing budget witness (Φ5).

**Runner.** The interpreter walks the DAG, charges edge traversals, evaluates guards, respects `AbortSignal`, and records every stage as a `control.stage` event. **Hot-swap** replaces the word only at cycle boundaries, preserving state, emitting `control.hotSwap{from, to, preservedState}`. There is no opaque scheduler: every selection is an event (Φ6).

## §6 — The Economy (β)

### 6.1 One arithmetic

A single `CostVector` over the ten dimensions; one table owns names, ceilings, and termination reasons. The grant test, the refusal reason, and the accumulation each exist exactly once.

### 6.2 Reservations

`reserve(bid) → token` debits before execution; `settle(token, actual)` refunds the delta. Starvation becomes impossible to hide: a denied reservation is a typed `budget.exhausted` event naming the dimension.

### 6.3 Pricing

```text
score(op) = (ΔK + ΔG + ΔH) / (λ_c·C + λ_r·R + λ_h·H_human)
  ΔK expected epistemic gain   ΔG expected goal progress   ΔH expected homeostatic gain
  C  compute cost              R  risk cost                H  human-attention cost
```

### 6.4 Degradation ladder (graceful by construction)

| Pressure | Behavior |
|---|---|
| Low | explore, enrich, elaborate |
| Medium | prioritize goals and proofs |
| High | conserve, degrade to symbolic-only, request help |

### 6.5 Thermodynamic mode (optional coordinate, `β.pricing = 'boltzmann'`)

Hard cutoffs become soft: `P(pursue) ∝ exp(−ΔE/T)`, where cognitive temperature *T* interpolates exploration ↔ exploitation. Total budget remains fixed — heat redistributes, it never creates.

## §7 — The Admission Functional (α)

Four gates become one function, instantiated four times:

```text
A_θ : Candidate × Context → Decision
A_θ(x) = route( trust(x), risk(x), reversibility(x), θ )
```

**Commit-path routing** (generalizes the action autonomy ladder to *every* mutation):

| Trust | Risk | Reversibility | Path |
|---|---|---|---|
| High | Low | High | auto-commit |
| High | Med | High | shadow-commit → promote |
| Med | Low | High | provisional + decay |
| Med | Med | Med | human review |
| Any | High | Low | strong proof **or** human approval |
| Low | High | Low | reject |

**Orientation.** Each boundary declares `interior` (fail-closed: deny on uncertainty) or `closure` (fail-open: admit provisionally, log the fault). SeNARS₀: ingress interior, egress closure. The epistemic firewall is a clause of `A_θ`, not a separate gate: no decision whose `axis = teleological` may write `Belief.(f,c)`; reward may move attention and policy weights, never truth.

**Gate monotonicity (lemma):** adding judgment stages can only narrow admission, never widen it.

## §8 — Provenance (π)

- **One fold.** `fold : Log → State` is pure; `replay ∘ log ≅ id` is a property test, not a hope. Checkpoints accelerate bootstrapping; they never substitute for the log.
- **One thread.** `correlationId` is minted at stimulus and rides every transaction, event, gate decision, budget refusal, and scheduler choice — stimulus → cycle → derivation → action is navigable in both directions.
- **Causal queries.** *Which stimulus caused this belief? Which derivation led to this action? Which judge vetoed this candidate? Which exhaustion degraded this cycle? Which config edit changed this behavior?*
- **Independent verification.** The derivation verifier lives in `core`, imports nothing from the engine, transcribes the truth table rather than importing it, and its drift against engine arithmetic is *measured by a test*. `verifyRecord` is the one proof checker; a CLI runs it in CI on every change.
- **Tiered audit.** Full proof for high-risk commits; sampled lineage for routine — depth is a coordinate (π.depth), not a code fork.

## §9 — Governed Reflexivity (ρ)

### 9.1 Filtration

| Level | Mutates | Authority |
|---|---|---|
| F₀ | nothing (frozen) | — |
| F₁ | knobs / parameters | auto if low-risk |
| F₂ | strategy selection | proposal or auto |

| F₄ | code / config patches | shadow CI + **external immutable arbiter** |
| Constitution | Φ itself | human + external audit — outside the tower entirely |

**Invariant:** no level approves itself. Truth sits outside the tower.

### 9.2 Meta-controller as learned object

The scheduler is a portfolio — deliberative, reactive, curious, conservative, creative, social, repair, consolidating — each a `CognitiveProgram`:

```ts
interface CognitiveProgram {
  stageGraph; budgetAllocation; proposerPortfolio;
  verificationPolicy; autonomyPolicy; learningPolicy;
}
```

Selection is itself a governed transaction (`kind: 'control'`), logged with rationale and expected utility, replayable via `replayControlState(events)`. The meta-controller is Ω applied to its own control state: it perceives through the same ports, infers through the same substrate, proposes through the same ledger, and is budgeted by its own scope.

### 9.3 The transcendence clause

`ReasonerConfig` is a **first-class cognitive object.** At F₃+ the system may propose *new reasoners* — config edits, new flavor candidates — which are shadow-evaluated against the parity and feasibility benches before any governance decision. The MetaReasoner's product is the design space; its learning loop can move through that space. The framework's output is its own input. This is bounded by construction: Φ is not an editable coordinate at any level below human + external audit.

## §14 — Semantics & Parity

**Denotation.** `⟦·⟧ : ReasonerConfig → Reasoner` maps configurations to runnable systems:

```text
⟦c⟧ : Stimulus* → 𝒫(Event*)     bounded, governed, fold-consistent
```

**Laws.**

1. **Compositionality:** `⟦c₁ ⊗ c₂⟧ = ⟦c₂⟧ ∘ ⟦c₁⟧`.
2. **Feasibility:** `Φ(c) = false ⟹ ⟦c⟧` undefined — rejected at load, never partially instantiated.
3. **Replay:** `replay(log(⟦c⟧(s))) ≅ ⟦c⟧(s)` for all c, s.
4. **Conservation:** strata are conservative — `Ω₀ ⊑ Ω₁ ⊑ Ω₂ ⊑ Ω₃ ⊑ Ω₄`; later strata add coordinates, never move invariants.
5. **Parity (the regression anchor):** `⟦SeNARS₀⟧` is behaviorally identical to the current production runtime — verified by the existing E2E pipeline and event-log equivalence. `SeNARS₀` never diverges from production behavior; it is the fixed point against which all abstraction drift is measured.

## §15 — Efficiency Doctrine

Abstraction must cost nothing on the hot path. Enforced, not aspirational:

1. **Compiled control.** The control word compiles to a flat dispatch table of stage pointers + guard predicates. Stage dispatch performs no allocation; graph traversal is pointer-chasing with inline integer budget checks.
2. **Integer economy.** Budget checks are fixed-width integer arithmetic on `CostVector`; a reservation is one subtraction; settlement is one addition. No floating point, no allocation in the grant path.
3. **O(1) commit fast path.** Ledger append is schema-validated write-ahead; the fold is lazy and checkpointed — readers never scan the log on the hot path.
4. **Pay for nothing.** Conservative extension means unused strata are absent branches, not dormant code: Ω₀ carries no meta-controller, Ω₁ carries no manifold. Kernel size is budgeted (Ω₀: five effects, one transaction type, one fold — a handful of files).
5. **Devirtualization.** Port interfaces with a single configured implementation resolve statically; the port boundary costs zero at runtime while keeping the seam for alternative substrates.
6. **Bench ceilings as CI gates:** cycle throughput ≥ current SeNARS; ledger commit ≤ 1 ms; stage dispatch ≤ 50 µs; memory overhead ≤ 10%; meta-controller selection ≤ 5 ms.
